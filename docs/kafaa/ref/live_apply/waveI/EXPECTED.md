### 4a. Table grants after the apply

Scope: the 11 tables the wave-I migrations create. Each one revokes every API-role privilege and grants SELECT only, so on live (where the Supabase default privileges give anon and authenticated ALL on a new `public` table) the rows below must hold exactly as listed. On a PostgreSQL 17 project ALL also held MAINTAIN; it must not appear below either. The PGlite dry run (`verify-live-bundle.mjs`) starts from the Supabase default privileges and checks this table after the parts.

Every privilege anon, authenticated and PUBLIC hold on the 11 `public.kafaa_*` relations this wave's migrations create (local PGlite after every migration; live must give the same rows, with the same table lists). Any other row, any other privilege in a list, or a PUBLIC row means a grant is still open: stop and compare. The earlier waves' tables are out of scope here: their grants are fixed schema-wide by the separate `audit-fixes` PR.

```sql
select g, p, count(*)::int n, string_agg(t, ', ' order by t) tables from (
  select c.relname t, case when a.grantee = 0 then 'PUBLIC' else a.grantee::regrole::text end g, string_agg(a.privilege_type, ', ' order by a.privilege_type) p
    from pg_class c join pg_namespace s on s.oid = c.relnamespace cross join lateral aclexplode(c.relacl) a
   where s.nspname = 'public' and c.relkind in ('r', 'p', 'v', 'm', 'f')
     and c.relname = any(array['kafaa_automation_adoptions', 'kafaa_automations', 'kafaa_consortium_cohorts', 'kafaa_consortium_members', 'kafaa_consortium_visits', 'kafaa_external_certs', 'kafaa_grant_applications', 'kafaa_grant_rounds', 'kafaa_learning_balances', 'kafaa_study_time_requests', 'kafaa_transition_plans'])
     and (a.grantee = 0 or a.grantee::regrole::text in ('anon', 'authenticated'))
   group by 1, 2) x group by 1, 2 order by 1, 2;
```
